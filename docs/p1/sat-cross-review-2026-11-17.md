# P1 cross-review — SAT code, specification, and paper draft

**Review date:** 2026-11-17  
**Reviewed branches:** `p2/w4-sat` (SAT implementation and W4 analysis), `p1/w3-experimental-protocol-rc` (protocol and paper integration)  
**Scope:** consistency review of the implemented formulation and the modular SAT paper draft. This is not P2 technical sign-off or a benchmark result review.

## Findings that are consistent

1. **Problem and notation.** `CONTRACT.md`, `docs/sat_spec.md`, `src/sat/pairwise.py`, and `src/sat/order.py` use the same ABP objective and decision threshold: a bijection from vertices to labels \(1,\ldots,n\), with every edge endpoint separation at least \(K\).
2. **Pairwise encoding.** The \(n^2\) assignment variables, per-vertex ALO/AMO constraints, per-label ALO/AMO constraints, and no-good distance clauses match the implementation. The distance clause count for \(1\leq K<n\) is \(2m\sum_{d=1}^{K-1}(n-d)\).
3. **Order encoding.** The variable meaning \(o_{v,p}=1\iff f(v)\leq p\), monotonic-chain clauses, no-good permutation constraints, and no-good distance constraints match `src/sat/order.py`. The order encoding has no separate AMO factor; changing its AMO metadata does not change the CNF.
4. **Optimization search.** `solve_sat` initializes `lo=0`, `hi=n`, probes `K=lo+1`, verifies each SAT labeling, jumps to `B+1` after a verified incumbent, and uses the first UNSAT threshold to prove optimality. Reaching the natural maximum \(n-1\) also closes the interval and proves optimality.
5. **Feasibility verification.** The decoders and shared `verify()` recompute the labeling's objective. The appendix correctly identifies the trust boundary: the project verifies the feasible labeling but does not independently check a SAT solver's UNSAT proof.
6. **Runtime comparability.** SAT's internal `t_total` and Exact's internal `t_total` do not necessarily cover identical work. The paper draft now states that RQ3 cross-family runtime comparisons must use the shared runner's `wall_time`.

## Items that remain open before freeze or final paper

1. **Pilot budget mismatch.** The committed W3 RQ1/RQ2 CSV run IDs show `time_limit=60.0` seconds. The current Experimental Protocol v1.0-rc §6.2 specifies 1,800 seconds for RQ1/RQ2 pilot runs. The 60-second pilot tables are valid historical observations, but they do not satisfy the later 1,800-second plan. The group must either explicitly retain the historical evidence and revise the protocol budget, or repeat the pilot under 1,800 seconds and revisit canonical selection.
2. **Memory enforcement versus measurement.** `solve_sat()` samples memory; it does not itself enforce `Config.memory_limit`. Official enforcement belongs to the shared runner/OS Job Object. The Linux RSS fallback is for importability/testing only and must not be mixed with Windows official-host memory values.
3. **Official host and hard-cap sign-off.** The 12.0 GiB canonical config value follows P1's candidate Windows host, but P3 must confirm that this is the actual official host and provide the OS-level kill/MO evidence. No `v1.0` tag is justified yet.
4. **G3 raw evidence.** The previous `70/70 PASS` report was generated by code that derived its denominator from observed rows and included non-Core pilot rows. It is now marked superseded. The corrected analysis uses the 40 unique Core pilot IDs (30 distinct RQ1 runs plus 10 new Glucose runs; the 10 CaDiCaL runs are reused) and requires raw JSON triage. Those raw JSON files are not present in the reviewed Git tree, so G3 remains pending.
5. **Official dataset/results.** The 24 Harwell–Boeing `.mtx.rnd` files and official `runs.csv` were not available in the reviewed Git tree. No final RQ1/RQ2/RQ3 claims, figures, or solver ranking on those official instances can be signed off.
6. **P2/P3 acceptance.** This is a P1 code/spec consistency review. P2 must confirm the SAT derivation and paper wording; P3 must confirm the runner schema, raw-record/triage integration, cap enforcement, checkpoint/resume, dry-run, and official queue.

Keep issues #25, #28–#30, and #31–#38 open where their remaining gates apply. The SAT methodology and proof appendix drafts are now available under `paper/`, but they are modular drafts, not an integrated or final manuscript.
